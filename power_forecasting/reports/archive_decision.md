# Проверка архивных прогнозов погоды

> Исторический отчёт первоначальной проверки. Пользователь принял Previous Runs fixed-lead methodology; текущий pipeline завершён. См. dataset_report.md, point_in_time_validation.md и README. Точное время публикации по-прежнему не заявляется. Первоначальные 36 проб теперь в weather_preflight_report.csv; weather_coverage_report.csv содержит полный проверенный интервал по переменным.

Статус: **PHASE 2 BLOCKED — историческая доступность информации не доказана**.
Проверено 23 сентября 2026 года. Это не вывод о невозможности задачи или отсутствии архивов вообще.

## Что проверено фактически

Выполнены 42 тестовых запроса для двух отдельных координат. 36 запросов проверяют три модели через два API на трёх датах. Ещё 6 проверяют отдельный продукт ECMWF HRES. Все ответы, URL запросов, HTTP-коды и время получения сохранены в `data/cache/weather/{model}/`.

Проверенные даты: 2023-03-11, 2025-01-01, 2026-02-01. Это выборочные проверки, а не полный скан архива. Фактические earliest_available_date и latest_available_date всего архива пока НЕ установлены. Границы непустых значений в пробах нельзя выдавать за границы архива.

Для Previous Runs проверены суффиксы previous_day1 и previous_day2. Непустые поля в успешных пробах имеют 24 значения за сутки для обоих смещений. У ECMWF IFS025 порывы ветра на проверенных датах 2025 и 2026 остаются null.

Результаты доступны в `weather_coverage_report.csv` и `ecmwf_hres_probe.csv`. Запросы сделаны отдельно для каждой турбины. Провайдер может вернуть одну и ту же ячейку сетки для обеих точек; запрошенные и возвращённые координаты сохранены.

## Почему сборка остановлена

1. **Отсутствует время публикации.** Previous Runs возвращает значения с фиксированными смещениями, но в полученных ответах нет `run_time` и `published_at` для каждой точки. Сейчас нельзя доказать условие `weather information timestamp <= forecast_issue_time` для произвольного запуска в 00:00.
2. **Часы модели и часы публикации различаются.** Single Runs выбирает инициализацию по `run`. Глобальная модель обычно рассчитывается ещё несколько часов. Условие `run_time <= issue_time` само по себе недостаточно. HTTP Date и `retrieved_at` относятся к сегодняшнему скачиванию; `generationtime_ms` — к обработке API-запроса. Они не подтверждают историческую публикацию.
3. **Разное покрытие продуктов.** Документация Single Runs объявляет большинство архивов с 2026-04-02. Это позже тестового февраля. Наличие HRES не доказывает наличие IFS025, GFS или ICON.
4. **Происхождение HRES нужно уточнить.** Документация описывает раннюю историю HRES с 2024-03-14 как IFS Cycle 49R1 hindcasts. Ретроспективный расчёт может иметь историческую дату инициализации, но быть создан позднее. До проверки происхождения нельзя объявлять его доступным в прошлом. Сам факт наличия чисел в API не решает эту проблему.
5. **Timezone SCADA не определён.** Географическое положение не доказывает настройки часов SCADA. Также неизвестны начало/конец интервала и задержка доступности наблюдений. Последнее влияет на rolling MAE и динамические веса.

Частичные пропуски переменных сами по себе не являются причиной блокировки: их можно сохранить как NaN. Причина остановки — недоказанная доступность информации на исторический момент.

## Варианты продолжения

1. **Исследовать семантику Previous Runs и построить консервативный отбор.** Проверить исходный код хранения предыдущих прогнозов, правила обновления и публикации для каждого провайдера. Выбирать достаточно старый прогноз, только если для него можно обосновать верхнюю границу времени доступности до issue_time. Затем просканировать границы покрытия каждой переменной; ранние пропуски оставить NaN. Это наиболее простой по объёму данных путь, но его пригодность ещё предстоит доказать. Фиксированный суффикс previous_day1 нельзя автоматически приравнивать к одному запуску системы на весь D1.
2. **Использовать исходные архивы оперативных запусков.** Для GFS, ECMWF и ICON найти GRIB/NetCDF с подтверждённым происхождением и временем публикации. Кандидаты — NOAA NODD/NCEI, архивы ECMWF и DWD либо архивный поставщик. Доступность всех трёх за нужный период пока не подтверждена; могут потребоваться учётная запись или платный доступ. Реанализ и retrospectively generated hindcasts не заменяют оперативный прогноз.
3. **Получить у организаторов архив или утверждённый источник.** Нужны operational run ID, время публикации либо документированная безопасная граница доступности, координаты/ячейки и единицы. Такой архив подключается локальным адаптером с теми же проверками.

Для любого варианта требуется подтвердить `timezone` и смысл timestamp SCADA. Полная проверка датасета и ансамбль запускаются только после снятия этих ограничений. По прямой инструкции из промпта переход к PHASE 3–10 сейчас не выполнен.

## Источники

- [Open-Meteo Single Runs](https://open-meteo.com/en/docs/single-runs-api) — покрытие, инициализация против публикации, описание hindcasts HRES.
- [Open-Meteo Previous Runs](https://open-meteo.com/en/docs/previous-runs-api) — фиксированные временные смещения и ограничения истории.
- [Open-Meteo Historical Forecast](https://open-meteo.com/en/docs/historical-forecast-api) — непрерывная серия, составленная из первых часов последовательных запусков; не готовая замена point-in-time срезу.
- [Официальный код Open-Meteo](https://github.com/open-meteo/open-meteo/blob/main/Sources/App/Controllers/ForecastapiController.swift) — поддерживаемые идентификаторы моделей.
- [NOAA GFS в AWS Open Data](https://registry.opendata.aws/noaa-gfs-bdp-pds/) — кандидат для отдельной проверки первичного архива.

Документация проверена на указанную дату. Полные тела ответов API сохранены локально, поэтому результаты проб можно воспроизвести без повторных запросов.
